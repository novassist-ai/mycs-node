# Bastion DNS Design

This document describes the internal DNS stack on the bastion appliance: PowerDNS Authoritative server, Recursor, DNSDist load balancer, and Pi-hole ad blocking in Docker.

## Overview

Internal DNS is configured by `scripts/config/configure_powerdns` during `init_instance`, **after** `configure_docker` (Pi-hole runs in Docker).

The stack provides:

- **Authoritative DNS** for internal zones (e.g. `test-uk1.local`)
- **Recursor** for upstream resolution
- **DNSDist** as a front-end load balancer / router
- **Pi-hole** for blocklists on general Internet queries

Road-warrior VPN clients and LAN hosts use the bastion admin IP (`config_powerdns_ns_ip`, typically `config_server_admin_itf_ip`) as their DNS server.

## Architecture

```mermaid
flowchart TB
  subgraph clients [Clients]
    LAN[LAN hosts]
    VPN[VPN clients]
  end

  subgraph bastion [Bastion admin IP]
    DD[DNSDist :53]
    AUTH[PowerDNS Authoritative<br/>127.0.0.1]
    REC[PowerDNS Recursor]
    PH[Pi-hole Docker]
  end

  subgraph upstream [Upstream]
    RES[config_server_dns_resolvers]
  end

  LAN --> DD
  VPN --> DD
  DD -->|local zones| AUTH
  DD -->|other queries| REC
  DD -->|filtered path| PH
  REC --> RES
  AUTH --> SQLite backend
```

**Query routing (DNSDist):**

- Internal `.local` zones → Authoritative server (before Pi-hole, because VPN clients cannot resolve `.local` via Pi-hole alone)
- General queries → Recursor and/or Pi-hole per dnsdist rules

## Configuration Model

From `/etc/mycs/config.yml` (generated by `cloud-inceptor/modules/bastion-config`):

| Config key | Purpose |
|------------|---------|
| `powerdns.dns_zones` | Comma-separated authoritative zones (e.g. `test-uk1.local`) |
| `powerdns.dns_records` | Static records `name:ip,...` (e.g. `jumpbox.test-uk1.local:172.20.64.133`) |
| `powerdns.allowed_subnets` | Subnets permitted to query (LAN + VPN subnet) |
| `powerdns.ns_ip` | IP DNSDist binds to (admin interface) |
| `powerdns.api_port` | PowerDNS API port |
| `powerdns.api_key` | API authentication key |
| `server.dns_resolvers` | Upstream resolvers for recursor fallback |

Example:

```yaml
powerdns:
  dns_zones: test-uk1.local
  dns_records: jumpbox.test-uk1.local:172.20.64.133
  allowed_subnets: 172.20.64.0/22,192.168.111.0/24
  ns_ip: 172.20.64.189
  api_port: 8888
  api_key: "<secret>"
```

`configure_network` sets system resolvers to `config_powerdns_ns_ip` when PowerDNS is configured, otherwise `config_server_dns_resolvers`.

## configure_powerdns Behaviour

Script: `scripts/config/configure_powerdns`  
Marker: `/usr/local/etc/.powerdns_installed`

High-level steps:

1. Load Pi-hole Docker image from tarball saved at build time (`pihole.tgz`).
2. Configure PowerDNS Authoritative (SQLite backend, API, loopback listener).
3. Configure Recursor (YAML config for PDNS 5.x).
4. Define local zones and static records from config.
5. Configure DNSDist front-end on `powerdns.ns_ip:53`.
6. Start Pi-hole container with updatelists; wait for DNS service.
7. Apply dnsdist rules: LAN zones to recursor before Pi-hole.
8. Enable and start `pdns`, `pdns-recursor`, `dnsdist` systemd units.
9. Schedule Pi-hole blocklist update job.

Pi-hole container receives environment for admin password, DNS listening, and volume mounts under `/data`.

## Component Details

### PowerDNS Authoritative

- Package: `pdns-server`, `pdns-backend-sqlite3`
- SQLite database under `/data/powerdns/` (persisted on data volume)
- Serves configured zones and static records
- API enabled for dynamic updates (port from config)

### PowerDNS Recursor

- Package: `pdns-recursor`
- Forwards non-local queries toward upstream resolvers
- Configured via YAML (`/etc/powerdns/recursor.yml`)

### DNSDist

- Package: `dnsdist`
- Listens on `powerdns.ns_ip` (admin NIC)
- Routes queries based on qname and source subnet
- LAN `.local` zones routed to recursor/authoritative path before Pi-hole

### Pi-hole (Docker)

- Image: `mycs/pihole:latest` (built during `install_packages` with updatelists)
- Provides ad/tracker blocklists for general DNS queries
- Requires Docker (`configure_docker` runs first)

## Client Integration

| Client type | DNS server | Notes |
|-------------|------------|-------|
| LAN hosts | Bastion admin IP | Via DHCP option or static config from Terraform |
| OpenVPN clients | Pushed in `server.conf` | From PowerDNS or `vpn.dns_servers` |
| IPsec clients | In `.mobileconfig` / strongSwan | From PowerDNS config |
| WireGuard clients | Client `DNS =` setting | Set in generated client config |

`powerdns.allowed_subnets` must include both LAN CIDR and road-warrior VPN subnet for clients to query DNS.

For cross-site VPN access to remote internal names, ensure DNS queries can reach the bastion and that forward zones/records exist for required hostnames.

## Troubleshooting

### Check services

```bash
systemctl status pdns pdns-recursor dnsdist docker
docker ps | grep pihole
```

### Test resolution from bastion

```bash
dig @127.0.0.1 jumpbox.test-uk1.local
dig @<admin_ip> jumpbox.test-uk1.local
```

### Test from VPN client

```bash
dig @<bastion_admin_ip> jumpbox.test-uk1.local
nslookup jumpbox.test-uk1.local <bastion_admin_ip>
```

### DNSDist / recursor logs

```bash
journalctl -u dnsdist -n 50 --no-pager
journalctl -u pdns-recursor -n 50 --no-pager
journalctl -u pdns -n 50 --no-pager
```

### Pi-hole container

```bash
docker logs pihole
docker exec pihole pihole status
```

### Common issues

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| `.local` names fail from VPN | Pi-hole path used instead of authoritative | DNSDist rules; `allowed_subnets` includes VPN CIDR |
| No DNS at all | DNSDist not bound to admin IP | `ss -ulnp | grep :53`; `powerdns.ns_ip` matches admin interface |
| Pi-hole not starting | Docker not ready | `configure_docker` log; `docker ps -a` |
| Records missing | Static records not in config | `/etc/mycs/config.yml` → `powerdns.dns_records` |

### Re-run configuration

```bash
sudo rm -f /usr/local/etc/.powerdns_installed
sudo /usr/local/lib/cloud-inceptor/configure_powerdns 2>&1 | tee /var/log/configure_powerdns.log
```

### Init log

```bash
sudo cat /var/log/configure_powerdns.log
```
